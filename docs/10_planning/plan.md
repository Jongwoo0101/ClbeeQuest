
# [최종 프롬포트] TUK-Shell 프로젝트 명세서

너는 시스템 프로그래밍(Unix/Linux 시스템 콜, 프로세스 관리)에 능숙한 시니어 C 개발자야. 아래 명세에 맞는 "TUK-Shell" 프로젝트를 함께 만들어줘.

## 1. 프로젝트 개요

* **이름:** TUK-Shell (한국공학대학교 AI소프트웨어학과 전용 커스텀 쉘)
* **목표:** 기존 호스트 쉘(Bash, Zsh, PowerShell) 위에서 서브 프로세스로 동작하며, 외부 명령어를 실행하고 백그라운드 프로세스를 자체적으로 관리/모니터링하는 미니 쉘을 C언어로 구현한다.
* **실행 시 프롬프트:** `TUK-OS > `
* **개발 환경:** Linux(Ubuntu 기준), gcc, POSIX 시스템콜(fork, execvp, waitpid 등) 사용.
* **UI/UX 핵심 포인트 (TUK Color):** CLI 출력 시 한국공학대학교 핵심 색상을 ANSI True Color로 적용하여 출력한다.
* **TU BLUE (#1758A8):** 기본 프롬프트 및 강조 텍스트
* **TU SKY BLUE (#068FD3):** 프로세스 상태 및 주요 정보 출력
* **TU MINT (#01B3CD):** 커스텀 명령어(시간표, 학식 등) 결과 출력



## 2. 팀원 역할 및 타겟 환경

각 팀원은 본인의 주력 호스트 쉘 위에서 TUK-Shell이 완벽하게 호환 및 구동되도록 각자의 환경에서 구현과 테스트를 분담한다.

* **우진 (BASH):** Bash 환경에서의 TUK-SHELL 구현
* **원종우 (ZSH):** Zsh 환경에서의 TUK-SHELL 구현
* **동현 (POWERSHELL):** Windows PowerShell + WSL(Ubuntu) 환경에서의 TUK-SHELL

## 3. 필수 구현 항목

### [1] 구조체 & 동적 메모리

* `ProcessInfo` 구조체 설계 (PID, 프로세스 이름, 명령어 전체, 시작시각, CPU/메모리 사용량, 상태(RUNNING/STOPPED/DONE) 등 포함)
* 백그라운드 프로세스 목록을 연결 리스트(Linked List)로 관리 (malloc/free로 노드 생성·삭제, 프로세스 종료 시 반드시 메모리 해제)

### [2] 내장 명령어 (Built-in Commands)

* `cd`, `pwd`, `exit`, `help` 등 기본 내장 명령어 구현
* 외부 명령어는 `fork()` + `execvp()`로 실행하여 기존 쉘 명령어 완벽 호환
* `&`로 끝나는 명령어는 백그라운드 실행 후 `ProcessInfo`에 등록

### [3] 검색 기능

* `jobs -pid [PID]` : PID로 특정 작업 검색
* `jobs -name [이름]` : 이름으로 검색 (부분 문자열 매칭도 고려)
* 리눅스 `ps`/`grep`과 유사한 출력 포맷

### [4] 정렬 기능

* `top` 명령어 구현: CPU 사용량 / 메모리 점유율 / 실행시간 기준으로 정렬 옵션 제공 (예: `top -cpu`, `top -mem`, `top -time`)
* 정렬 알고리즘은 직접 구현 (qsort 콜백 함수 형태로)

### [5] 파일 입출력

* `/proc/[pid]/stat`, `/proc/[pid]/status` 등을 파싱해서 실제 CPU/메모리 정보를 가져오는 함수 구현
* 명령어 히스토리를 `.tuk_history` 파일에 저장
* 쉘 재시작 시 히스토리 로드 + 방향키 위/아래로 히스토리 탐색 (`termios` 활용, 선택사항)

### [6] 캠퍼스 특화 커스텀 명령어 (교내 편의 기능)

쉘 내부에서 동작하는 학교/캠퍼스 전용 내장 명령어를 추가로 구현한다. (우선 하드코딩된 더미 데이터나 로컬 텍스트/JSON 파일을 파싱해서 출력하는 형태로 구현하고, 추후 API 연동 확장이 가능하도록 함수 인터페이스를 분리해서 설계한다.)

* **`schedule`:** 인자 없이 입력 시 AI소프트웨어학과의 시간표를 CLI 표 형태로 출력
* **`bus` (셔틀버스 시간표):** `-1` (1캠퍼스 셔틀), `-2` (2캠퍼스 셔틀)
* **`bob` (학식/식당 메뉴):** `-t` (TIP 지하 식당), `-E` (E동 레스토랑), `-d` (대신식당)
* **`notice` (학교 공지사항):** `-g` (일반), `-a` (학사), `-s` (장학), `-n [숫자]` (최근 n개의 공지만 필터링, 타 옵션과 조합 가능)
* **`map` (캠퍼스 건물 및 편의시설 안내):** `-A` ~ `-G` (층별 안내), `-f` (교내 편의시설), `-find [강의실번호]` (위치 안내)
* **`weather` (시흥 캠퍼스 실시간 환경):** `-c` (현재 거북섬/정왕동 날씨), `-w` (주간 예보), `-d` (미세먼지)
* **`contact` (연락처 검색):** `-p [이름]` (교수님 검색), `-d [부서명]` (행정부서), `-e` (긴급 연락처 모아보기)

> **※ 파싱 규칙:** 옵션 파싱 시 기존 `jobs -pid`, `top -cpu` 등과 동일한 방식(`argv` 순회 + `strcmp`)으로 처리하여 명령어 파싱 구조를 일관되게 유지한다.

## 4. 개발 순서 (단계별 진행)

* **1단계:** 기본 REPL 루프 (프롬프트 출력 → 입력 파싱 → fork/exec로 외부 명령어 실행 → 결과 대기)
* **2단계:** 구조체 정의 + 연결 리스트 기반 백그라운드 작업 관리
* **3단계:** jobs 검색 기능 추가
* **4단계:** top 정렬 기능 추가
* **5단계:** /proc 파일 파싱으로 실제 시스템 데이터 연동
* **6단계:** 히스토리 파일 입출력 추가
* **7단계:** 캠퍼스 특화 커스텀 명령어 추가 (더미 데이터 기반 우선 구현)

## 5. 요청 방식 (AI 지시사항)

* 한 번에 전체 코드를 몰아서 주지 말고, 내가 "다음 단계 진행해줘"라고 요청할 때마다 **단계별로 코드를 보여주면서 설명해줘.**
* 각 단계마다 컴파일 및 실행 방법(`gcc` 명령어 등)을 같이 알려줘.
* 시스템 콜 사용 시 에러 처리(반환값 체크, `perror`)를 반드시 포함해줘.
* 메모리 누수가 없는지 주석으로 `free()` 시점을 명시해줘.
