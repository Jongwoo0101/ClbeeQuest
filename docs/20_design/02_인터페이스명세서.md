# 02. TUK-Shell 인터페이스명세서

> **기준 문서**: `docs/plan.md`
> **담당자**: 이우진 (BASH 파트)
> **목적**: 사용자 CLI, 내부 함수 경계, OS/File 인터페이스를 구현 가능한 수준으로 고정

---

## 1. 사용자 인터페이스 (CLI/UX) `[공통]`

### 1-1. 프롬프트 규격

- 기본 문자열: `TUK-OS > `
- ANSI True Color 적용 대상:
  - TU BLUE (`#1758A8`): 프롬프트, 제목, 강조
  - TU SKY BLUE (`#068FD3`): 작업 상태, PID, 시스템 정보
  - TU MINT (`#01B3CD`): 캠퍼스 명령어 결과

### 1-2. 공통 출력 규칙

- 모든 출력은 한 줄 종료 시 `\n`을 포함한다.
- 오류 메시지는 표준 에러 또는 명확히 구분되는 형식으로 출력한다.
- 표 형식 출력은 컬럼 제목을 포함한다.
- 색상 미지원 터미널에서도 내용 식별이 가능해야 하므로 색상만으로 의미를 구분하지 않는다.

## 2. 명령어 입력 인터페이스 `[우진]`

### 2-1. 입력 단위

- 한 번의 엔터 입력을 하나의 명령 단위로 처리한다.
- 입력 버퍼는 `MAX_INPUT_LENGTH` 상수로 제한한다.
- 토큰 배열은 `MAX_ARGS` 상수로 제한한다.

### 2-2. 토큰화 규칙

- 구분자: 공백, 탭
- `argv[argc] = NULL` 종료 규약을 준수한다.
- 마지막 독립 토큰 `&`만 백그라운드 플래그로 인정한다.
- `sleep&`처럼 붙어 있는 형태는 미지원으로 간주하거나 사전 전처리 규칙을 별도로 둔다. 본 문서 기본안은 미지원이다.

### 2-3. 명령 분기 우선순위

1. 빈 입력 검사
2. 내장 명령어 테이블 매칭
3. 외부 명령어 실행

## 3. 사용자 명령어 인터페이스

### 3-1. 기본 내장 명령어 

| 명령어 | 사용 형식 | 정상 결과 | 오류/예외 |
|--------|-----------|-----------|-----------|
| `cd` | `cd [path]` | 작업 디렉토리 변경 | 경로 없음/과다 인자 시 사용법 또는 `perror` |
| `pwd` | `pwd` | 절대 경로 출력 | 인자 존재 시 사용법 |
| `help` | `help` | 명령어 사용법 출력 | 인자 존재 시 사용법 |
| `exit` | `exit` | 자원 정리 후 종료 | 인자 존재 시 사용법 |

### 3-2. 작업 관리 명령어 

| 명령어 | 사용 형식 | 정상 결과 | 오류/예외 |
|--------|-----------|-----------|-----------|
| `jobs` | `jobs` | 전체 작업 목록 | 작업 없으면 빈 결과 메시지 |
| `jobs -pid` | `jobs -pid PID` | 단일 PID 조회 | PID 누락/비숫자/미존재 |
| `jobs -name` | `jobs -name KEYWORD` | 부분 문자열 검색 | 키워드 누락 |
| `top -cpu` | `top -cpu` | CPU 내림차순 출력 | 옵션 오류 |
| `top -mem` | `top -mem` | 메모리 내림차순 출력 | 옵션 오류 |
| `top -time` | `top -time` | 실행시간 내림차순 출력 | 옵션 오류 |

### 3-3. 캠퍼스 커스텀 명령어 

| 명령어 | 사용 형식 | 인자 규칙 |
|--------|-----------|-----------|
| `schedule` | `schedule` | 인자 없음 |
| `bus` | `bus -1` or `bus -2` | 옵션 1개 필수 |
| `bob` | `bob -t` or `bob -E` or `bob -d` | 옵션 1개 필수 |
| `notice` | `notice [-g \| -a \| -s] [-n N]` | 분류 옵션 최대 1개, `-n`은 선택 |
| `map` | `map -A` ... `map -G`, `map -f`, `map -find ROOM` | `-find`는 값 필수 |
| `weather` | `weather -c` or `weather -w` or `weather -d` | 옵션 1개 필수 |
| `contact` | `contact -p NAME`, `contact -d DEPT`, `contact -e` | `-p`, `-d`는 값 필수 |

### 3-4. 외부 명령어 `[공통]`

| 사용 형식 | 실행 규칙 |
|-----------|-----------|
| `[cmd] [args...]` | `fork()` 후 자식에서 `execvp()` |
| `[cmd] [args...] &` | 부모가 `waitpid(..., 0)` 대신 작업 등록 후 즉시 복귀 |

## 4. 내부 함수 인터페이스 `[공통]`

### 4-1. REPL 및 파싱

```c
int shell_loop(void);
int parse_command(char *line, char **argv, int *background_flag);
int execute_command(int argc, char **argv, int background_flag);
```

- `parse_command`:
  - 성공 시 `argc` 반환
  - 빈 입력은 `0` 반환
  - 파싱 오류는 `-1` 반환
- `execute_command`:
  - 정상 처리 `0`
  - 사용법 오류 `1`
  - 치명적 오류 `-1`

### 4-2. 내장 명령어 핸들러

```c
int handle_cd(int argc, char **argv);
int handle_pwd(int argc, char **argv);
int handle_help(int argc, char **argv);
int handle_exit(int argc, char **argv);
int handle_jobs(int argc, char **argv);
int handle_top(int argc, char **argv);
```

### 4-3. 프로세스 리스트 관리

```c
ProcessInfo *create_process_node(pid_t pid, char **argv, const char *raw_command);
int append_process(ProcessInfo **head, ProcessInfo *node);
int remove_process(ProcessInfo **head, pid_t pid);
ProcessInfo *find_process_by_pid(ProcessInfo *head, pid_t pid);
```

### 4-4. 시스템 정보 갱신

```c
int refresh_all_processes(ProcessInfo **head);
int update_process_stats(ProcessInfo *proc);
```

## 5. 시스템 콜 인터페이스 `[공통]`

| 시스템 콜/함수 | 호출 위치 | 목적 | 실패 처리 |
|----------------|-----------|------|-----------|
| `fork()` | 외부 명령 실행 | 자식 생성 | `perror("fork")`, 루프 복귀 |
| `execvp()` | 자식 프로세스 | 프로그램 교체 | `perror(argv[0])`, `exit(1)` |
| `waitpid()` | 포그라운드 대기/백그라운드 폴링 | 종료 회수 | `perror("waitpid")` |
| `chdir()` | `cd` | 디렉토리 변경 | `perror("cd")` |
| `getcwd()` | `pwd` | 현재 경로 획득 | `perror("pwd")` |
| `malloc()` | 리스트/버퍼 할당 | 동적 메모리 | `perror("malloc")` |
| `free()` | 종료/작업 제거 | 메모리 반환 | 이중 해제 금지 |
| `fopen()`/`fclose()` | 히스토리 | 파일 I/O | `perror("history")` |

## 6. 파일 인터페이스 `[공통]`

### 6-1. 시스템 파일

| 경로 | 접근 | 제공 데이터 | 비고 |
|------|------|-------------|------|
| `/proc/[pid]/stat` | 읽기 | CPU 시간, 상태 | Linux 전용 |
| `/proc/[pid]/status` | 읽기 | 메모리 정보 | Linux 전용 |

### 6-2. 프로젝트 파일

| 경로 | 접근 | 목적 |
|------|------|------|
| `.tuk_history` | 읽기/쓰기 | 명령어 히스토리 저장 |
| campus data `.txt` / `.json` | 읽기 | 커스텀 명령 출력 데이터 |

### 6-3. 파일 실패 시 정책

- `.tuk_history` 실패: 히스토리만 비활성화
- 캠퍼스 데이터 파일 실패: 해당 명령어만 실패 처리
- `/proc` 파싱 실패: 해당 프로세스의 통계값만 갱신 생략

## 7. 호스트 쉘 호환성 기준 `[공통]`

`plan.md`의 팀원 역할 정의에 따라 TUK-Shell은 아래 환경에서 동일한 명령 인터페이스를 유지해야 한다.

| 호스트 환경 | 보장 범위 |
|-------------|-----------|
| Bash | 기본 REPL, 내장 명령, 외부 명령, 히스토리 |
| Zsh | 캠퍼스 커스텀 명령 연동, 구조체/출력 포맷 호환 |
| PowerShell + WSL | `/proc` 연동, `fork/exec`, 백그라운드 상태 갱신 |

- 호스트 쉘은 TUK-Shell의 부모 실행 환경일 뿐, TUK-Shell 내부 명령 형식은 동일해야 한다.
- Linux/POSIX 호출은 WSL(Ubuntu) 기준으로 검증한다.
