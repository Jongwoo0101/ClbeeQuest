# 03. TUK-Shell 파이프라인명세서

> **기준 문서**: `docs/plan.md`
> **담당자**: 이우진 (BASH 파트)
> **목적**: 실행 흐름, 상태 전이, 자원 회수 시점을 단계별로 정의

본 문서는 TUK-Shell의 시작부터 종료까지의 파이프라인을 정의하며, `plan.md`의 개발 순서가 실제 실행 흐름으로 어떻게 반영되는지 설명한다.

---

## 1. 전체 파이프라인 개요

```text
프로그램 시작
  -> 초기화
  -> REPL 입력 대기
  -> 파싱
  -> 내장/외부 명령 분기
  -> 포그라운드 대기 또는 백그라운드 등록
  -> 상태 갱신 및 자원 회수
  -> REPL 복귀
  -> 종료 정리
```

---

## 2. 초기화 파이프라인 

### 2-1. 순서

```text
[실행] ./tuk_shell
    |
    +-> [1] 런타임 상태 구조체 초기화
    |
    +-> [2] ProcessInfo 리스트 헤드 = NULL
    |
    +-> [3] .tuk_history 열기 및 기존 이력 로드
    |       `-> 없으면 생성, 실패하면 히스토리 비활성화
    |
    `-> [4] 프롬프트 루프 진입
```

### 2-2. 초기화 실패 정책

- 히스토리 파일 실패: 경고 후 계속 진행
- 메모리 할당 실패: 현재 단계가 필수 초기화라면 `exit(1)`
- 색상 설정 실패 개념은 없으며 ANSI 문자열 출력만 수행

---

## 3. REPL 입력 파이프라인

### 3-1. 상세 흐름

```text
[프롬프트 출력]
    |
    +-> [1] TU BLUE 색상으로 "TUK-OS > " 출력
    |
    +-> [2] 한 줄 입력 수신
    |       `-> EOF면 종료 파이프라인으로 이동
    |
    +-> [3] 빈 줄 여부 검사
    |       `-> 빈 줄이면 다음 반복
    |
    +-> [4] 원본 문자열 보관
    |
    +-> [5] 토큰화
    |
    +-> [6] 마지막 토큰 '&' 검사
    |       `-> 발견 시 background_flag = 1, 토큰 제거
    |
    `-> [7] 히스토리 파일/메모리 버퍼 동기화
```

### 3-2. 입력 예외 처리

- 입력 길이 초과: 남은 버퍼를 비우고 오류 출력
- 토큰 수 초과: 실행하지 않고 오류 출력
- 공백만 있는 줄: 무시

---

## 4. 명령 실행 파이프라인

### 4-1. 분기 로직

```text
[argv[0] 기준 분기]
    |
    +-> [A] 내장 명령어
    |       +-> 인자/옵션 검증
    |       +-> 대응 함수 호출
    |       `-> REPL 복귀
    |
    `-> [B] 외부 명령어
            +-> fork()
            +-> 자식: execvp()
            `-> 부모: foreground/background 분기
```

### 4-2. 내장 명령 처리 규칙

- `cd`, `pwd`, `help`, `exit`, `jobs`, `top`, 캠퍼스 명령어는 쉘 프로세스 내부에서 직접 실행한다.
- 백그라운드 플래그가 설정된 내장 명령은 금지 목록 여부를 확인한다.
- 사용법 오류는 프로세스를 생성하지 않고 즉시 반환한다.

### 4-3. 외부 명령 처리 규칙

#### 포그라운드

```text
부모 -> waitpid(pid, &status, 0)
     -> 자식 종료 코드 수집
     -> REPL 복귀
```

#### 백그라운드

```text
부모 -> ProcessInfo 생성
     -> 리스트 등록
     -> PID 및 시작 메시지 출력
     -> REPL 즉시 복귀
```

### 4-4. 시작 메시지 형식

```text
[bg] pid=12345 command="sleep 30"
```

출력 색상은 TU SKY BLUE를 사용한다.

---

## 5. 백그라운드 상태 갱신 파이프라인 `[공통]`

### 5-1. 갱신 트리거

- REPL 한 사이클 시작 직전
- `jobs` 실행 직전
- `top` 실행 직전

### 5-2. 순서

```text
[리스트 순회]
    |
    +-> [1] waitpid(pid, &status, WNOHANG) 로 종료 여부 확인
    |
    +-> [2] 종료되지 않았으면 update_process_stats(proc) 호출
    |
    +-> [3] 상태/CPU/메모리 값 갱신
    |
    `-> [4] 종료가 확인되면 종료 메시지 출력 후 노드 제거/free
```

### 5-3. 종료 메시지 형식

```text
[done] pid=12345 exit=0 command="sleep 30"
```

### 5-4. 상태 전이

| 이전 상태 | 이벤트 | 다음 상태 |
|-----------|--------|-----------|
| `RUNNING` | 정상 종료 감지 | `DONE` |
| `RUNNING` | 정지 상태 감지 | `STOPPED` |
| `STOPPED` | 재개 감지 | `RUNNING` |
| `DONE` | 정리 완료 | 리스트 제거 |

---

## 6. `jobs` / `top` 전용 조회 파이프라인 

### 6-1. `jobs`

```text
jobs 호출
  -> 백그라운드 상태 갱신
  -> 옵션 해석
  -> 필터 조건 적용
  -> 표 출력
```

### 6-2. `top`

```text
top 호출
  -> 백그라운드 상태 갱신
  -> 리스트를 배열로 복사
  -> qsort(compare_fn)
  -> 정렬 결과 표 출력
  -> 임시 배열 해제
```

---

## 7. 히스토리 파이프라인

### 7-1. 쓰기

```text
명령 확정
  -> 빈 명령인지 확인
  -> .tuk_history에 append
  -> fflush()
  -> 메모리 버퍼에 추가
```

### 7-2. 읽기

```text
프로그램 시작
  -> .tuk_history open
  -> 한 줄씩 메모리 버퍼 적재
```

### 7-3. 장애 시 동작

- 파일 쓰기 실패: 현재 명령 실행은 계속한다.
- 메모리 버퍼 추가 실패: 파일 저장만 유지하고 탐색 기능은 제한 가능하다.

---

## 8. 캠퍼스 명령어 파이프라인 

```text
campus command 입력
  -> 명령어 식별
  -> 옵션 검증
  -> 전용 핸들러 호출
  -> 더미 데이터 파일 또는 내부 데이터 로드
  -> TU MINT 색상으로 결과 출력
  -> REPL 복귀
```

- BASH 파트는 파서와 핸들러 디스패치까지만 책임진다.
- 데이터 소스 파싱 실패는 해당 명령만 실패시키고 쉘은 계속 유지한다.

---

## 9. 종료 파이프라인 

```text
exit 명령 또는 EOF
    |
    +-> [1] 남은 백그라운드 프로세스 리스트 순회
    |       `-> 각 노드 free()
    |
    +-> [2] 히스토리 파일 flush/close
    |
    `-> [3] 종료 코드 반환
```

### 9-1. 종료 시 주의사항

- 종료 시 백그라운드 자식을 강제 종료할지 여부는 현재 문서 범위 밖이다.
- 최소 요구사항은 쉘 내부 메모리 정리와 파일 스트림 종료다.
- 해제 순서는 리스트 노드 -> 히스토리 -> 기타 버퍼 순으로 유지한다.

## 10. 에러 처리 원칙 `[공통]`

| 위치 | 에러 | 처리 |
|------|------|------|
| 파싱 | 잘못된 옵션/인자 | 사용법 출력 후 루프 복귀 |
| `fork()` | 자식 생성 실패 | 오류 출력 후 루프 복귀 |
| `execvp()` | 외부 명령 실행 실패 | 자식에서 오류 출력 후 `exit(1)` |
| `waitpid()` | 회수 실패 | 오류 출력 후 해당 루프 계속 |
| `malloc()` | 메모리 할당 실패 | 현재 작업 중단, 필요 시 종료 |
| 히스토리 파일 | 열기/쓰기 실패 | 히스토리만 비활성화 |
| `/proc` 파싱 | 파일 접근 실패 | 통계 갱신 생략 |
