# 05. TUK-Shell 개발철칙명세서

> **대상**: TUK-Shell 프로젝트 (특히 Bash 파트 개발자 이우진)
> **기준 문서**: `docs/01_상세기능명세서.md` ~ `docs/04_검증및추적명세서.md`
> **핵심 철칙**: **`main.c`는 진입점 및 흐름 제어만 담당하며, 절대로 100줄을 초과하지 않는다.**

---

## 1. 코드 아키텍처 및 모듈화 철칙

### 1-1. `main.c` 100줄 제한 규칙
- `main.c`는 쉘의 초기화, REPL 루프 제어, 그리고 종료 처리의 **구조적 흐름**만 제어한다.
- 실질적인 명령 실행, 문자열 파싱, 프로세스 관리, 시스템 정보 수집, 캠퍼스 명령어 처리 등은 모두 기능별 소스 파일(`*.c`) 및 헤더 파일(`*.h`)로 모듈화하여 분리한다.
- 가독성과 유지보수성 극대화를 위해 `main.c` 내에 헬퍼 함수를 남용하지 않고 호출부 인터페이스만 남긴다.

### 1-2. 기능별 소스 파일 구성 철칙
소스 코드는 아래와 같이 철저히 분할 구현되어야 한다.   
(필요에 따라 이 구조는 변경해도 됨)

```text
src/bash/
├── main.c           # REPL 루프 및 메인 제어 흐름 (★ 100줄 이하)
├── parser.c/h       # 명령어 입력 파싱 및 & 플래그 판별
├── commands.c/h     # 내장 명령어(cd, pwd, help, exit) 핸들러
├── process.c/h      # ProcessInfo 구조체 및 연결 리스트 관리, fork/execvp 실행
├── system_info.c/h  # /proc/stat 및 status 파싱 연동 (동현 파트와 인터페이스 일치)
├── campus.c/h       # 캠퍼스 특화 커스텀 명령어 연동 (원종우 파트와 인터페이스 일치)
└── history.c/h      # .tuk_history 파일 입출력 및 탐색 기능
```

## 2. 메모리 및 리소스 관리 철칙

### 2-1. 동적 메모리 (`malloc` / `free`) 철칙
- **해제 시점 주석 필수**: 동적 할당(`malloc`)이 발생하는 모든 지점에는 대응하는 해제(`free`) 시점을 설명하는 주석을 반드시 명시해야 한다.
- **백그라운드 회수 시 즉시 해제**: `waitpid(..., WNOHANG)`를 통해 백그라운드 자식 프로세스의 종료가 감지되는 즉시, 해당 노드를 `ProcessInfo` 연결 리스트에서 안전하게 제거하고 메모리를 `free()` 한다.
- **쉘 종료 시 완전 누수 방지**: 사용자가 `exit` 명령어를 입력하거나 EOF가 감지되었을 때, 연결 리스트에 남아 있는 모든 프로세스 노드와 힙 메모리에 할당된 명령어 버퍼 등을 완전히 `free()` 한 뒤 최종 프로세스를 종료한다.

### 2-2. 파일 스트림 철칙
- 쉘 시작 시 연 `.tuk_history` 파일 스트림은 쉘 종료 시점(`exit`)에 반드시 `fclose()` 되어 쓰기 버퍼가 디스크에 물리적으로 기록(`fflush` 포함)되도록 보장한다.

## 3. 에러 처리 및 예외 상황 대응 철칙

### 3-1. 시스템 콜 리턴값 검증 철칙
- `fork()`, `execvp()`, `waitpid()`, `chdir()`, `getcwd()`, `malloc()`, `fopen()` 등 모든 POSIX 시스템 콜 및 표준 라이브러리 함수의 반환값을 절대 무시하지 않고 검증한다.
- 호출 실패 시 반드시 `perror("상황 설명")`를 호출하여 표준 에러 출력에 시스템 에러 메시지를 명확히 출력한다.

### 3-2. 예외 복구 및 동작 격리
- **히스토리 장애 격리**: `.tuk_history` 파일 접근에 실패하더라도 경고 메시지만 출력할 뿐, 쉘의 메인 REPL 루프가 종료되어서는 안 된다.
- **자식 프로세스 에러 전파 차단**: `fork()` 후 자식 프로세스 내에서 `execvp()` 실행이 실패했을 때, 에러 내용을 `perror`로 출력하고 **반드시 `exit(1)`로 즉시 자식 프로세스를 종료**시켜 부모 프로세스(TUK-Shell)가 자식의 에러를 정상 감지하고 자원을 회수할 수 있도록 한다. (자식 프로세스 내부에서 쉘 메모리 free를 시도하지 않는다.)
- **캠퍼스 데이터 장애 격리**: 커스텀 캠퍼스 명령어(`bob`, `bus` 등)의 더미 데이터 로드나 파싱에 실패하더라도, 해당 명령 오류만 출력하고 쉘 실행 상태를 정상 유지한다.

## 4. 인터페이스 및 사용자 경험(UI/UX) 철칙

### 4-1. 색상 테마 및 포맷 준수
- 프롬프트는 무조건 `TUK-OS > ` 형식을 취하며, 색상은 **TU BLUE (`#1758A8`)**를 적용한다.
- 백그라운드 등록 및 종료 알림 등 시스템 메시지 출력은 **TU SKY BLUE (`#068FD3`)**를 사용한다.
- 캠퍼스 특화 명령어의 출력 결과는 **TU MINT (`#01B3CD`)**를 사용하여 일관된 사용자 경험을 보장한다.
- 색상 지원이 안 되는 환경(단색 터미널)에서도 텍스트만으로 정상 식별이 가능하도록 괄호(`[]`) 및 텍스트 상태 표기(예: `[bg]`, `[done]`)를 생략하지 않는다.

### 4-2. 입력 제약 조건 관리
- 사용자의 한 줄 입력 최대 길이는 `MAX_INPUT_LENGTH` 상수를 초과할 수 없으며, 인자 개수는 `MAX_ARGS`로 고정 제약한다.
- 버퍼가 넘치거나 토큰 개수가 규격을 초과하는 경우 에러 메시지를 출력하고 실행을 즉시 취소한다.
