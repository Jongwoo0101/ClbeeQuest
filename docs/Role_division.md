## 🛠️ 최적의 3인 역할 분담 모델 (이틀 완성용)

앞서 확정한 **"TUK-Shell" (커스텀 쉘 & 프로세스 매니저)** 프로젝트를 기준으로 역할을 나눴습니다. 코드 병합 시 충돌을 최소화하도록 모듈을 분리했습니다.

### 🧑‍💻 [Developer A] Mac 유저 1: Shell Core & REPL 파트 (Project Manager)

쉘의 근간을 잡고, 사용자 입력을 처리하는 핵심 파트를 담당합니다.

* **담당 모듈:** `main.c`, `parser.c`, `builtin.c`
* **세부 업무:**
1. **REPL 루프:** `TUK-OS >` 프롬프트 출력 및 사용자 입력(문자열) 처리.
2. **명령어 파싱:** 입력된 문자열을 파싱하여 인자(arguments)를 분리하고, 파이프(`|`)나 백그라운드 기호(`&`)를 식별.
3. **기본 내장 명령어:** `cd`, `pwd`, `exit`, `help` 등 프로세스 생성 없이 쉘 내부에서 처리되는 기본 명령어 구현.
4. **히스토리 관리:** 입력된 명령어 히스토리를 저장하고 파일(`.tuk_history`)에서 불러오는 기능 구현.
5. **PM 역할:** 전체 프로젝트의 `Makefile`을 작성하고, GitHub에서 팀원들의 코드를 취합 및 병합(Merge)하는 역할. 결과보고서 초안 작성 리드.


* **장점:** POSIX 호환 환경인 Mac에서 무리 없이 개발 및 테스트가 가능합니다.

### 🧑‍💻 [Developer B] Mac 유저 2: Data Structure & TUK Custom 파트

팀원 A가 파싱해 준 데이터를 바탕으로 자료구조를 관리하고, 이 프로젝트의 킬링 포인트인 '캠퍼스 커스텀 명령어'를 전담합니다.

* **담당 모듈:** `list.c` (또는 `process.c`), `tuk_custom.c`
* **세부 업무:**
1. **구조체 설계:** `ProcessInfo` 구조체 정의.
2. **연결 리스트 구현:** 백그라운드 프로세스를 관리할 연결 리스트(Linked List)의 추가/검색/삭제 로직 개발 (메모리 누수 방지에 집중).
3. **정렬 알고리즘:** 나중에 `top` 명령에서 사용할 정렬 기능(qsort 등)의 뼈대 구현.
4. **TUK 커스텀 명령어:** `schedule`, `bus`, `bob`, `notice`, `map` 등 프롬프트에 정의된 캠퍼스 특화 명령어 구현 (더미 데이터 기반 출력).


* **장점:** 시스템 콜보다는 C언어 본연의 자료구조 처리와 문자열 출력 로직이 주를 이루므로, Mac 환경에서 독립적인 단위 테스트(Unit Test)가 매우 수월합니다.

### 🧑‍💻 [Developer C] Windows 유저 1 (WSL/리눅스 환경 필수): System Call & /proc 파트

팀에서 유일하게 (WSL 또는 VM을 통해) 리눅스 환경을 온전히 사용할 수 있으므로, 리눅스 전용 기능과 복잡한 프로세스 제어를 전담합니다.

* **담당 모듈:** `executor.c`, `sysinfo.c`
* **세부 업무:**
1. **외부 명령어 실행:** `fork()`와 `execvp()`를 이용해 일반 외부 명령어(예: `ls -l`)를 실행하는 로직 구현.
2. **백그라운드 프로세스 처리:** 명령어가 `&`로 끝날 때 프로세스를 백그라운드로 넘기고, `waitpid(..., WNOHANG)` 등을 사용해 좀비 프로세스(Zombie Process)를 수거하는 로직 구현.
3. **리눅스 /proc 파싱:** `/proc/[pid]/stat` 파일 등을 파싱하여 프로세스의 실제 CPU 및 메모리 사용량 정보를 추출해 오는 함수 구현. (Mac에서는 불가능한 작업)
4. **top 명령어 완성:** B가 만들어둔 정렬 알고리즘 뼈대에, 자신이 파싱해 온 실제 시스템 리소스 데이터를 결합하여 완성.


* **장점:** WSL/리눅스 환경에서만 가능한 핵심 시스템 콜 기능을 맡아 병목 현상을 방지합니다.

---

> **Tip:** 최종 발표 자료(PPT)와 결과보고서는 마감 전날(16일) 저녁부터 **A(전체 구조), B(차별점/커스텀 기능), C(기술적 난이도/시스템 콜)**가 각자 자신이 개발한 파트를 중심으로 작성하여 합치는 것이 가장 효율적입니다.
