너는 시스템 프로그래밍(Unix/Linux 시스템 콜, 프로세스 관리)에 능숙한 
시니어 C 개발자야. 아래 명세에 맞는 "TUK-Shell" 프로젝트를 함께 만들어줘.

## 프로젝트 개요
- 이름: TUK-Shell (커스텀 쉘 & 프로세스 매니저)
- 목표: bash/zsh처럼 명령어를 실행하고, 백그라운드 프로세스를 
  자체적으로 관리/모니터링하는 미니 쉘을 C언어로 구현
- 실행 시 프롬프트: `TUK-OS > `
- 개발 환경: Linux(Ubuntu 기준), gcc, POSIX 시스템콜(fork, execvp, waitpid 등) 사용

## 필수 구현 항목

### 1. 구조체 & 동적 메모리
- `ProcessInfo` 구조체 설계 (PID, 프로세스 이름, 명령어 전체, 
  시작시각, CPU/메모리 사용량, 상태(RUNNING/STOPPED/DONE) 등 포함)
- 백그라운드 프로세스 목록을 연결 리스트(Linked List)로 관리
  (malloc/free로 노드 생성·삭제, 프로세스 종료 시 반드시 메모리 해제)

### 2. 내장 명령어 (Built-in Commands)
- cd, pwd, exit, help 등 기본 내장 명령어
- 외부 명령어는 fork() + execvp()로 실행
- `&`로 끝나는 명령어는 백그라운드 실행 후 ProcessInfo 등록

### 3. 검색 기능
- `jobs -pid [PID]` : PID로 특정 작업 검색
- `jobs -name [이름]` : 이름으로 검색 (부분 문자열 매칭도 고려)
- 리눅스 ps/grep과 유사한 출력 포맷

### 4. 정렬 기능
- `top` 명령어 구현: CPU 사용량 / 메모리 점유율 / 실행시간 기준으로 
  정렬 옵션 제공 (예: `top -cpu`, `top -mem`, `top -time`)
- 정렬 알고리즘은 직접 구현 (qsort 콜백 함수 형태로)

### 5. 파일 입출력
- `/proc/[pid]/stat`, `/proc/[pid]/status` 등을 파싱해서 
  실제 CPU/메모리 정보를 가져오는 함수 구현
- 명령어 히스토리를 `.tuk_history` 파일에 저장
- 쉘 재시작 시 히스토리 로드 + 방향키 위/아래로 히스토리 탐색 
  (termios 활용, 선택사항)

### 6. 캠퍼스 특화 커스텀 명령어 (교내 편의 기능)
쉘 내부에서 동작하는 학교/캠퍼스 전용 내장 명령어를 추가로 구현한다.
(실제 데이터 연동이 어려운 경우, 우선 하드코딩된 더미 데이터나 로컬 텍스트/JSON 
파일을 파싱해서 출력하는 형태로 구현하고, 추후 API 연동 확장이 가능하도록 
함수 인터페이스를 분리해서 설계한다.)

- **`schedule`**
  - 인자 없이 입력 시 AI소프트웨어학과의 시간표를 CLI 표 형태로 출력

- **`bus`** (셔틀버스 시간표)
  - `-1` : 1캠퍼스 셔틀 시간표 출력
  - `-2` : 2캠퍼스 셔틀 시간표 출력

- **`bob`** (학식/식당 메뉴)
  - `-t` : TIP 지하 식당 식단 출력
  - `-E` : E동 레스토랑 시간표 출력
  - `-d` : 대신식당 식단 출력

- **`notice`** (학교 공지사항)
  - `-g` : 일반 공지사항 최신 목록 출력 (General)
  - `-a` : 학사 공지사항 최신 목록 출력 (Academic)
  - `-s` : 장학 공지사항 최신 목록 출력 (Scholarship)
  - `-n [숫자]` : 최근 n개의 공지만 필터링해서 출력 (다른 옵션과 조합 가능, 예: `notice -a -n 5`)

- **`map`** (캠퍼스 건물 및 편의시설 안내)
  - `-A` ~ `-G` : 특정 동(A동, E동, TIP 등)의 층별 주요 시설(강의실, 랩실) 안내
  - `-f` : 교내 편의시설(편의점, 카페, 프린터 위치, ATM 등) 위치 출력 (Facilities)
  - `-find [강의실번호]` : 강의실 번호(예: E-301) 입력 시 위치 및 가는 길 안내

- **`weather`** (시흥 캠퍼스 날씨 및 환경)
  - `-c` : 현재 캠퍼스 실시간 날씨 및 기온 (Current)
  - `-w` : 이번 주 캠퍼스 주간 날씨 예보 (Weekly)
  - `-d` : 오늘 미세먼지·초미세먼지 농도 출력 (체육활동 참고용, Dust)

- **`contact`** (교내 주요 부서 및 교수님 연락처 검색)
  - `-p [이름]` : 교수님 성함 검색 시 연구실 위치, 이메일, 내선번호 출력 (Professor)
  - `-d [부서명]` : 행정부서(학사지원팀, 취업진로팀 등) 연락처 및 위치 출력 (Department)
  - `-e` : 긴급 연락처(경비실, 시설관리팀, 보건실 등) 모아보기 (Emergency)

> 옵션 파싱 시 기존 `jobs -pid`, `top -cpu` 등과 동일한 방식(argv 순회 + 
> strcmp/문자열 비교)으로 처리하여 명령어 파싱 구조를 일관되게 유지한다.

## 개발 순서 (단계별로 진행해줘)
1단계: 기본 REPL 루프 (프롬프트 출력 → 입력 파싱 → fork/exec로 
   외부 명령어 실행 → 결과 대기)
2단계: 구조체 정의 + 연결 리스트 기반 백그라운드 작업 관리
3단계: jobs 검색 기능 추가
4단계: top 정렬 기능 추가
5단계: /proc 파일 파싱으로 실제 시스템 데이터 연동
6단계: 히스토리 파일 입출력 추가
7단계: 캠퍼스 특화 커스텀 명령어(schedule, bus, bob, notice, map, weather, contact) 
   추가 (더미 데이터 기반으로 우선 구현 후 필요 시 실데이터/파일 연동으로 확장)

## 요청 방식
- 한 번에 전체 코드를 몰아서 주지 말고, 단계별로 코드를 보여주면서 
  설명해줘. 각 단계마다 컴파일/실행 방법도 같이 알려줘.
- 시스템콜 사용 시 에러 처리(반환값 체크)를 반드시 포함해줘.
- 메모리 누수가 없는지 주석으로 free() 시점을 명시해줘.
