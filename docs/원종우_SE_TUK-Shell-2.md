## 담당 모듈
- `list.c` (또는 `process.c`)
- `tuk_custom.c`

## 착수 시점
- **연결 리스트 파트**: 이우진(A)의 결과물 없이도 오늘(7/15) 바로 시작 가능 → 최우선 착수
- **커스텀 명령어 파트**: 더미 데이터 기반이라 역시 독립적으로 오늘부터 병행 가능

## 세부 업무 (명세 2단계 기준)

1. **구조체 설계**: `ProcessInfo` 구조체 — PID, 프로세스 이름, 명령어 전체, 시작시각, CPU/메모리 사용량, 상태(RUNNING/STOPPED/DONE) 포함
2. **연결 리스트 구현**: 백그라운드 프로세스 관리용 Linked List 추가/검색/삭제 로직 (malloc/free 짝 맞추기, 메모리 누수 방지 집중)
3. **jobs 검색 기능 (3단계)**: `jobs -pid [PID]`, `jobs -name [이름]` (부분 문자열 매칭 포함) — 검색 로직은 B가 구현, A의 `builtin.c`에서 호출하는 구조로 인터페이스 사전 협의
4. **정렬 알고리즘 (4단계)**: `top -cpu`, `top -mem`, `top -time` 정렬 옵션용 qsort 콜백 함수 뼈대 구현 (실제 데이터는 C가 채움)
5. **TUK 커스텀 명령어 (7단계)** — 이 프로젝트의 킬링 포인트, 아래 전체를 B가 전담:
   - `schedule`: AI소프트웨어학과 시간표 CLI 표 출력 (인자 없음)
   - `bus -1 / -2`: 1·2캠퍼스 셔틀 시간표
   - `bob -t / -e / -d`: TIP지하/E동/대신식당 식단
   - `notice -g / -a / -s / -n [숫자]`: 공지 카테고리별 + 개수 필터 (옵션 조합 가능, 예: `notice -a -n 5`)
   - `map -A~-G / -f / -find [강의실번호]`: 동별 시설 안내, 편의시설, 강의실 위치 검색
   - `weather -c / -w / -d`: 실시간/주간 날씨, 미세먼지
   - `contact -p [이름] / -d [부서명] / -e`: 교수/부서/긴급 연락처 검색
   - 우선 하드코딩 더미 데이터 또는 로컬 텍스트/JSON 파싱으로 구현, 추후 API 연동 가능하도록 함수 인터페이스 분리
   - 옵션 파싱은 기존 `jobs -pid`, `top -cpu`와 동일하게 argv 순회 + strcmp 방식으로 통일

## 장점
시스템 콜보다 C언어 본연의 자료구조 처리와 문자열 출력 로직이 주를 이루므로, Mac 환경에서 독립적인 단위 테스트가 매우 수월함.

## 다른 팀원과의 접점
- **이우진(A)**: jobs 명령어 파싱(A)과 검색 로직(B) 간 함수 시그니처 사전 합의 필요
- **이동현(C)**: `top` 완성을 위해 B의 정렬 뼈대에 C가 파싱한 실제 `/proc` 데이터를 결합 — 데이터 구조(어떤 필드를 어떤 타입으로 넘길지) 사전 합의 필요
