## 🛠️ 단계별 상세 구현 및 검증 리포트

### ✅ 1단계: 기본 REPL 루프 (완료)

* **주요 내용:** `main.c` 등 모듈화, 프롬프트 컬러(TU BLUE) 적용, 파싱 로직, `cd/pwd/exit/help` 내장 명령어 처리.

### ✅ 2단계: 구조체 + 연결 리스트 (완료)

* **주요 내용:** `ProcessInfo` 구조체 정의, 동적 연결 리스트 관리, `waitpid(-1, &status, WNOHANG)`를 이용한 메모리 누수 방지 및 프로세스 상태 갱신(Reaping) 구현 완료.

### ✅ 3단계: `jobs` 검색 (완료)

* **주요 내용:** 연결 리스트 순회 출력, PID 정확 검색, Name 부분 문자열(`strstr`) 검색 로직 구현 및 예외 처리 완비.

### ✅ 4단계: `top` 정렬 (완료)

* **주요 내용:** 원본 연결 리스트의 훼손을 막기 위한 동적 배열 복사, `qsort`를 활용한 CPU/메모리/시간 내림차순 정렬 콜백 구현 및 누수 방지(`free`) 완료.

### ✅ 6단계: 히스토리 파일 입출력 (완료)

**1. 구현 내용 요약**

* **히스토리 누적 및 로드:** 쉘 종료 시 입력된 명령어를 `.tuk_history` 파일에 저장하고, 시작 시 기존 히스토리를 로드하여 누적 보존.
* **저장 데이터 최적화:** 단순 엔터(빈 줄) 및 공백/탭 등 의미 없는 입력은 기록하지 않도록 필터링 처리.
* **사용자 입력 보존:** 문법 오류(예: 리다이렉션 미지원)로 실행이 거부된 명령어도 사용자의 입력 맥락 보존을 위해 히스토리에 정상 기록.
* **장애 허용성(Fault Tolerance):** `.tuk_history` 파일 접근 실패 시 에러 로그만 출력하고 쉘의 핵심 REPL 루프에는 영향을 주지 않도록 시스템 격리 완료.

## 🚨 5단계 진입 전 통합 QA: 트러블슈팅 및 버그 픽스 리포트

5단계 본 구현에 앞서, 1~4단계 통합 검증 과정에서 발생한 예외 상황과 해결 내역입니다.

**1. 리다이렉션 미지원 처리 누락 (버그 수정 완료)**

* **증상:** `yes > /dev/null &` 입력 시 터미널 화면이 `>` 문자로 무한 도배되며 쉘 통제 불능 상태에 빠짐 (Ctrl+C 강제 종료 필요).
* **해결 방안:** `parser.c`에 `has_unsupported_syntax()` 검증 로직 추가. 파싱된 토큰 중 `>`, `<`, `|`, `"` 등이 포함될 경우 명시적 에러 메시지를 출력하고 즉시 실행을 거부하도록 안전장치 구현. (Valgrind 누수 검증 완벽 통과)

**2. UI 텍스트 겹침 현상 (정상 동작 분석 완료)**

* **분석 결과:** 파싱 버그가 아님. 백그라운드 프로세스 완료(`[done]`) 메시지가 비동기로 출력되는 타이밍과 사용자의 키보드 입력 시점이 겹치면서 화면상에서만 텍스트가 섞여 보이는 쉘 고유의 아티팩트(Artifact) 현상.

**3. 백그라운드 완료 알림 지연 현상 (정상 동작 분석 완료)**

* **분석 결과:** 버그가 아님. "REPL 한 사이클 시작 직전에 상태 갱신을 수행한다"는 초기 아키텍처 설계가 정확히 동작하고 있는 정상적인 흐름으로 판정.
