## 🚨 5단계 진입 전 통합 QA: 트러블슈팅 및 버그 픽스 리포트 (해결완료)

5단계 본 구현에 앞서, 1~4단계 통합 검증 과정에서 발생한 예외 상황과 해결 내역입니다.

**1. 리다이렉션 미지원 처리 누락 (버그 수정 완료)**

* **증상:** `yes > /dev/null &` 입력 시 터미널 화면이 `>` 문자로 무한 도배되며 쉘 통제 불능 상태에 빠짐 (Ctrl+C 강제 종료 필요).
* **원인:** `01_상세기능명세서.md 4-3`에 정의된 "리다이렉션/파이프/따옴표 미지원 처리" 규칙이 파서에 누락됨. 파서가 `>`와 `/dev/null`을 특수 기호가 아닌 `yes` 명령어의 일반 인자로 그대로 넘겨버려 발생한 논리적 오류.
* **해결 방안:** `parser.c`에 `has_unsupported_syntax()` 검증 로직을 추가. 파싱된 토큰 중 `>`, `<`, `|`, `"` 등이 포함될 경우 `error: redirection('>','<'), pipe('|'), quotes are not supported in this stage` 에러 메시지를 출력하고 즉시 실행을 거부하도록 안전장치 구현. (Valgrind 누수 검증: 38 alloc / 38 free 완벽 통과)

**2. UI 텍스트 겹침 현상 (정상 동작 분석 완료)**

* **증상:** 프롬프트에 사용자가 명령어를 입력하는 도중 `top -[done] pid=...` 처럼 문자가 겹쳐서 출력되는 현상.
* **분석 결과:** 파싱 버그가 아님. 백그라운드 프로세스 완료(`[done]`) 메시지가 비동기로 출력되는 타이밍과 사용자의 키보드 입력 시점이 물리적으로 겹치면서 터미널 화면상에서만 텍스트가 섞여 보이는 쉘 고유의 아티팩트(Artifact) 현상. 프로그램 내부 입력 버퍼에는 영향을 주지 않으므로 정상 동작으로 판정.

**3. 백그라운드 완료 알림 지연 현상 (정상 동작 분석 완료)**

* **증상:** `sleep N &` 작업 종료 직후가 아니라, 사용자가 엔터를 한 번 더 쳐야 `[done]` 메시지가 표출됨.
* **분석 결과:** 버그가 아님. `03_파이프라인명세서.md 5-1`에 명시된 "REPL 한 사이클 시작 직전에 상태 갱신을 수행한다"는 초기 아키텍처 설계가 정확히 동작하고 있는 정상적인 흐름으로 판정.
