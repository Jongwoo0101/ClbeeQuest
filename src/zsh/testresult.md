## 🛠️ 단계별 상세 구현 및 검증 리포트

### ✅ 1단계: 기본 REPL 루프 (완료)

* **주요 내용:** `main.c` 등 모듈화, 프롬프트 컬러(TU BLUE) 적용, 파싱 로직, `cd/pwd/exit/help` 내장 명령어 처리.

### ✅ 2단계: 구조체 + 연결 리스트 (완료)

**1. 구현 내용 요약**

* **자료구조:** `ProcessInfo` 구조체 정의 완료 (PID, Command, Status 관리).
* **메모리 제어:** 백그라운드 프로세스 등록 시 `malloc`, 종료 감지 시 노드 삭제 및 `free` (메모리 누수 방지 로직 적용 완료).
* **좀비 프로세스 회수:** REPL 루프 시작 직전 `waitpid(-1, &status, WNOHANG)`를 호출하여 종료된 백그라운드 프로세스 상태 갱신 및 메모리 회수(Reaping) 구현.

**2. 단계 검증 (7대 핵심 테스트 Pass 완료)**

* [x] **기본 등록:** `sleep 3 &` 실행 시 `[bg]` 메시지(TU SKY BLUE) 출력 후 즉시 REPL 대기 상태 복귀.
* [x] **다중 등록:** 여러 개의 백그라운드 프로세스 동시 등록 시 정상적으로 연결 리스트에 순차 append 됨.
* [x] **종료 감지 타이밍:** 백그라운드 작업 완료 후, Enter를 입력해 다음 REPL 사이클 진입 시 `[done]` 메시지 정상 출력 확인.
* [x] **포그라운드 병행:** 포그라운드 명령(`pwd` 등) 종료 후 대기 중이던 백그라운드 작업의 `[done]` 메시지 정상 갱신.
* [x] **내장 명령 예외:** `cd &` 등 내장 명령어의 백그라운드 실행 시도 시 거부 메시지 출력 및 쉘 유지 확인.
* [x] **명령어 오류 처리:** 존재하지 않는 명령어 백그라운드 실행 시, 자식 프로세스에서 에러 발생 후 부모 쉘에서 `exit=1`로 정상 회수(리스트 오염 없음).
* [x] **안전한 종료:** 백그라운드 작업 진행 중 `exit` 입력 시 크래시 없이 부모 쉘이 정상 종료됨.
